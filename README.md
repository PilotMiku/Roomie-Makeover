# Roomie-Makeover · 室友大改造

粉色少女风的像素寝室男娘养成模拟器。樱粉、奶白、爱心、蝴蝶结与蕾丝边框，陪伴大学室友自由表达、平等相处。所有素材本地内置。

当前为 **M7 完整体验 + 男娘进度与身份日常扩展**：成就、角色/服装/事件图鉴、可确认的新周目、本地音效和 PWA 离线；保留粉色自定义入住、多寝室、自动日常、换装、事件与五槽备份。实际检查与截图见 [docs/progress.md](docs/progress.md)，执行规范见 [AGENTS.md](AGENTS.md)。源码仓库：[PilotMiku/Roomie-Makeover](https://github.com/PilotMiku/Roomie-Makeover)。站点部署状态以 [GitHub Actions](https://github.com/PilotMiku/Roomie-Makeover/actions) 为准。

## 内容边界

所有玩家、角色及剧情 NPC 至少 18 岁。角色自由选择服装及风格，标签不对应医学判断。关系扮演限自愿、随时退出、非性化的成年室友互动，默认关闭，具有现实管理权的身份不参与。禁止露骨、胁迫及未成年人相关内容，禁止真人照片上传和未经授权素材。

## 本地开发

项目目录和英文项目名为 `Roomie-Makeover`，npm 包标识为小写 `roomie-makeover`。中文游戏名为“室友大改造”。使用 Node.js 24 LTS 与 npm。

```sh
nvm use
npm ci
npm run dev
```

访问终端打印的本地地址。依赖版本已记录在 `package-lock.json`，使用 `npm ci` 按锁定版本安装；首次安装需能访问 npm registry。更改依赖时运行 `npm install` 并一起提交 lockfile。

技术栈：Vite、React、TypeScript strict、Tailwind CSS 4 官方 Vite 插件、Zustand、React Router DOM 的 HashRouter、Zod。运行时仅需静态资源，不需要后端、远程 API、CDN 或 Python。

```sh
npm run format        # 格式化
npm run check         # 格式、Lint、类型、单元/组件测试、生产构建
npx playwright install chromium firefox
npm run test:e2e      # 先构建，再用生产预览测试桌面和 375px 触屏
PLAYWRIGHT_ENGINE=firefox npm run test:e2e -- e2e/smoke.spec.ts e2e/journey.spec.ts
npm run preview      # 手动检查生产页面
```

`npm run test:watch` 用于单元测试开发。如果已安装 Google Chrome，可运行 `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e` 使用本地 Chrome，无需额外下载 Chromium；CI 仍使用 Playwright 安装的 Chromium。测试需要允许启动浏览器和监听本地端口。

浏览器测试证据写入被 Git 忽略的 `artifacts/`、`test-results/` 和 `playwright-report/`。调试地址为 `http://127.0.0.1:5173/?fast=1#/room`（使用终端实际端口）；查询参数必须在 hash 前。进入或退出调试模式会重建计时锚点。

## 部署到 GitHub Pages

1. 创建自己的 GitHub 仓库，将本目录推送到默认分支 `main`；确保完整 `package-lock.json` 已提交。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 在 **Actions** 运行 `Check and deploy Pages`，或推送到 `main`。工作流在根路径和真实仓库子路径分别执行检查、构建与 Chromium 全流程、Firefox 主线冒烟测试；全部通过后发布检查过的 Pages artifact。PR 只检查，不发布。
4. 从成功的部署任务读取真实 Pages URL。检查首页、静态资源、直接打开 `#/settings` 和刷新。本项目仓库为 `PilotMiku/Roomie-Makeover`；线上访问是否可用需在部署成功后实际验证。

本地 `base` 为 `/`；Actions 使用 `GITHUB_REPOSITORY` 的真实仓库名；`owner/owner.github.io` 使用 `/`。不在代码中硬编码仓库占位符。

自定义域名：在 GitHub Pages 配置实际域名，并设置仓库 **Settings → Secrets and variables → Actions → Variables** 的 `VITE_BASE_PATH` 为 `/`。本地覆盖示例：

```sh
VITE_BASE_PATH=/Roomie-Makeover/ npm run build
VITE_BASE_PATH=/Roomie-Makeover/ npm run test:e2e
```

`Roomie-Makeover` 为本目录名示例，实际发布时由工作流解析真实仓库名。覆盖值自动规范化首尾斜杠；不接受外部 URL、查询参数及 `..`。

## 本地数据与隐私

更名保留原有存储键、Web Lock 名称和备份格式标识，以兼容现有进度与 JSON 文件；新的备份文件名以 `Roomie-Makeover-` 开头。游戏沿用 `roomdev:slot:1`，当前 schema 为 `1.6`，含提交版本与写入者标记。1.6 新增一次性标签起步加成、请假状态与归零回执；1.5 升级时，带“男娘”标签且进度不足 50 的旧角色一次补到 50，高于 50 的保留。归零旧状态在下一次规则结算时处理，不在刷新时反复扣减。1.5 新增六种面容、寝室宜居度、身份行动及其每日账本。1.4 升级默认温柔杏眼、宜居度 60，保留已有专业、外观和进度；达到新门槛的妆造会立即解锁。旧档依次按 `1.0 → 1.1 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6` 的对应格式验证与迁移，升级保留天数、床位、六维、发色/上衣色/肤色、衣物 ID 和成长。M3 新增下装颜色（旧档默认为 `#9b78b6`）及套装配色；旧的无配色套装补入默认色板，保留名称与服装。M4 新增心意点、互动回执、每日来源账本与寝室事件账本；旧档初始补入 20 心意点，保留已有互动次数，不补发往日资源或重抽往日事件。旧日结算没有记录来源明细及干湿分离状态，因此来源补零、设施标为“旧档未记录”。初始服装加入公共衣柜，达到成长/好感/事件条件的物品统一结算解锁。显示偏好仍使用独立的 `roomdev:preferences:1.0` 键。不识别版本、未知服装/事件引用、损坏或迁移失败时保留原文、锁定操作并提供原档下载，不自动覆盖。写入失败时保留内存状态并提供应急下载。

安全上下文中的现代浏览器使用 Web Locks 串行写入，并以提交原文比对和 `storage` 事件检测旧标签页；同槽发现冲突后锁定旧页，刷新载入最新档案，不同槽可独立游玩。缺少安全存档锁时仅允许内存游玩和应急下载，不写入已有存档，避免同时写入造成覆盖。请使用 HTTPS 或 localhost 地址的现代浏览器；真机与 Safari 验证仍待完成。

清理浏览器数据、换浏览器或使用无痕模式可能造成数据丢失。不提供账号、云同步或遥测。请定期导出 JSON 到自己保管的位置；离线缓存保存应用资源，不能替代存档备份。

## 五槽日记与备份恢复

从导航“回忆存档”进入 `#/saves`，最多五本独立日记。每本保存自己的室友、寝室、天数、六维、衣柜、随机种子、待选事件、设置与周目累计数据，默认保留最近 300 条日志。

1. **创建与改名**：在空槽填写名称后创建，随后“继续当前故事”进入身份与寝室自定义。创建不会覆盖已有存档；名称上限 40 字且遵守成年设定。每槽可单独改名，成长与室友不变。第一槽沿用原 `roomdev:slot:1`，其余使用 `roomdev:slot:2` 至 `:5`，旧档不搬家。
2. **切换与刷新**：“进入该存档”切换故事。当前槽先可靠保存，目标槽通过同一时间规则处理恢复可见时的补天；未选中的槽不会被后台逐个推进。当前选择使用标签页的 sessionStorage，刷新保留，不同标签页可选不同槽；新会话从第一槽选择其他故事即可。选择记忆被浏览器禁止时会明确提示，存档内容仍保留。
3. **导出**：当前槽“导出当前进度”，其他槽“导出 JSON”，浏览器下载单槽文件。导出完整有效状态，包含待选故事与解锁回执；存储失败时当前槽导出内存中最新进度。原始旧档保留在同一个本地记录中，迁移后及刷新后仍可“导出原始旧档”，字节原样不改。正常导出不复制旧档原文，避免递归嵌套。
4. **导入**：选择一个最大 **2 MiB（UTF-8 字节）** 的 JSON，先查看名称、版本、天数、成年室友/寝室数量、衣柜收藏与待选事件摘要，再选择目标槽并二次确认。支持旧版按序升级，Zod 验证根结构、数量上限、文本/年龄、属性范围、唯一 ID 与寝室/床位/服装/事件引用。任何解析、校验、迁移、冲突或写入失败均不替换原有效档案；目标在确认期间变化时需重新确认。
5. **恢复的默认值**：导入只将外层 slotId 绑定到所选槽，保留实体 ID、进度、种子、事件回执与待选决定；自动时间锚点按现在和当前调试模式重建，**不对备份中的离线时间追溯补天**。因此导入摘要中的游戏日不会因旧时间戳立即改变。其他槽不受影响；导入到其他槽后可自行选择进入。
6. **删除**：先确认删除指定槽的全部内容与内置旧档备份，其他槽不变。删除后留下不包含游戏内容的微小标记，旧标签页不能恢复写入已删故事；空槽不会自动生成新日记。未提供一键清空全部数据入口。
7. **异常恢复**：容量不足/权限拒绝时保留原档与内存进度，先导出当前进度，再释放空间或恢复权限，点“重试保存当前进度”。有未保存进度时阻止切槽，避免丢失。损坏、未来版本或迁移失败的槽可下载原始文件，在支持对应版本的应用恢复，或在备份后明确确认导入有效文件替换；其他槽可继续使用。原始旧档与升级档一起原子保存，存储空间不足时不会先覆盖旧档。

导入使用严格 UTF-8 解码，支持带 BOM 的 JSON 并将原始旧档 BOM 一起保留；非法编码会拒绝，不静默替换字符。请使用 UTF-8 编码的单槽 JSON 文件。

游戏 schema 为 `1.6`，多寝室沿用既有 rooms 数组与角色绑定；正式迁移注册表依次验证 `1.0 → 1.1 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6`，每步校验旧格式、最后校验当前格式。仅本地存储记录可附带 sourceRaw 原文元数据。小备份继续使用 revision/commitId/game 信封；超过 2 MiB 的普通表示会自动改为无损紧凑 JSON，在 2 MiB 限制内保留全部记录。所有写入继续使用与旧第一槽相同的锁，导入/删除/切换及异步游戏命令都会防止旧页面上下文串写。

## 多寝室与搬家

每个存档最多 **6 间寝室、24 位常住室友**；每间独立选择 4/6/8 人、床型和卫浴配置。空床与空寝室允许保留，床位总数可以超过 24，角色人数始终不能超过上限。

1. 完成第一间寝室入住后，在自定义工坊点“＋ 新建隔壁寝室”，填写名称、容量、床型和卫浴。保存后切到该房间的室友档案，可以添加室友。寝室长/自定义视角可管理全部内容，宿管/楼管可布置寝室；室友管理继续遵守身份权限。满 6 间或满 24 人时会禁用相应新增入口并说明。
2. 寝室页与工坊上方的房间卡片可切换视角，显示各房人数和床型；地址中的 `#/room?room=…&resident=…` 保留当前房间与室友，直接打开和刷新仍可定位。切换视角不改变游戏日、随机种子、成长或位置。
3. 寝室页展开“全体室友”，可按寝室、姓名/称呼/专业/标签查找，点结果定位到对应房间及档案。衣柜也支持按寝室筛选；空房会显示明确的添加室友入口，不显示虚假人物。
4. 在室友手记下方“带着成长，去隔壁住”选择目标寝室和空床，点“确认搬家”。目标已满、床已占用、床位被删除或室友已被其他操作移动时拒绝，原绑定不变。跨寝室只移到空床；同寝室继续使用原有拖拽/点选/“分配 / 交换”。
5. 搬家只改变 roomId/bedId，保留 ID、六维、穿搭/配色、标签、许可、成长、当天互动/送礼次数和进度额度。不会复制室友或重置次数；保存、切槽、导出导入及刷新后位置仍保留。
6. 已触发的故事保留原寝室和原参与者，不因搬家取消、重抽或发奖。事件列表、弹窗与历史标明来源寝室；玩家选择时仍按原参与者和当前日额度结算，角色即使住到隔壁也只领奖一次。
7. “进入下一天”统一结算当前存档的全部寝室，每位角色按结算时所住寝室的设施成长一次；共享心意点每天补给一次。自动补天同样覆盖全部寝室，分支队列仍全存档最多 3 个，每寝室每天最多一个主要事件，不自动代选。

24 人长期游玩时，本地普通记录超过 1 MiB 会无损紧凑保存；公开备份仅在普通表示超过 2 MiB 时切换格式。紧凑格式为 `roomdev-stats-tuples` / `1.0`，只把重复的六维字段名改为固定顺序数值行，导入先严格验证行结构与数量，再完整展开并校验当前游戏模型。没有删除、裁剪或近似任何值；旧档原文元数据仍与游戏一次原子保存。当前 1.6 备份需本次扩展或之后版本恢复，旧 1.3 紧凑大档仍可迁移，早期不认识该封装的版本会拒绝并保留原文。

## 自定义入住与日常玩法

1. 新玩家从首页点“定制我的入住故事”，或打开 `#/customize`，按“玩家身份 → 寝室配置 → 室友档案 → 入住”完成创建。界面默认大学校园背景，不设置年龄，也不需要年龄确认勾选。默认四人寝、公共卫浴、上床下桌；寝室初始为空，至少添加一位室友后入住，空床可保留。入住前游戏日暂停，草稿步骤会保存。旧档保留四位示例室友，不强制重建。
2. 在“室友手记”选择室友，再点目标床位；已有室友会交换，空床会移动。桌面可直接拖动床上的室友，投到地图外不变。键盘可聚焦室友与床位按钮后按 Enter，也可用“分配 / 交换”表单。
3. 在自定义工坊选择 4/6/8 人寝、上床下桌或双层床、独卫/公共卫浴/无洗手间；干湿分离仅独卫可选。床型切换保留绑定；缩容时保留仍有效的床位，将被移除床位上的室友安排到空床；入住人数超过目标容量时拒绝修改。
4. 点“进入下一天”结算六维，在下方查看实际增减与专业、设施来源。每角色每游戏日所有正向进度合计最多 +3；男娘进度达到 100 且已日结算至少 30 次才算阶段养成完成。在“星光纪念册”可选择继续或开启新周目。
5. 正常每累计现实 2 小时自动推进一天，只在页面可见时执行；初始化、重新可见、焦点恢复及可见期间每 15 秒检查。隐藏/关闭期间可累计，恢复每次最多补 7 天，超过的完整间隔舍弃，保留不足间隔的零头。手动结算保留计时锚点；边界同时到达时自动结算优先满足该次点击。时钟倒退会提示并重建安全锚点。
6. 刷新或切换页面保留天数、床位、六维、外观与日志。每槽最多保存 300 条结构化日志，本页显示最近 12 条；成长记录亦保留最近 300 条，总日结算次数独立累计。

身份包括寝室长、旁观者、室友成员、家长、宿管/寝室阿姨、楼管、辅导员、隔壁寝室成员、自定义。身份本身不占床或 24 人名额；只有显式创建常住室友才占床。初始配置阶段所有身份都可设置世界；入住后寝室长/自定义可管理寝室与室友，室友/隔壁成员可管理室友，宿管/楼管只可管理寝室，家长/辅导员不可改档案或换装。除旁观者外均可进行普通校园互动、送礼和选择事件；现实管理关系身份始终不能参与扮演。旁观者只可观察，也不能手动跳天。可随时回到身份页切换视角，进度保留。

室友档案可编辑姓名、称呼、代词、性格、专业、标签、发色/上衣颜色/肤色、床位与自愿扮演许可。重名允许但 ID 始终唯一；编辑不会重置成长，新增角色进度为 0。自定义专业采用日常基准倍率 1.0。移除需确认并释放床位，至少保留一名已入住室友。新角色内部默认 20 岁，旧档年龄保留，均继续经过至少 18 岁的存档校验；页面不展示年龄数字或反复强调成年。未成年人暗示、超长文本、床位冲突与人数超限会被阻止。

全局与角色两层关系扮演许可默认关闭，两者同时打开且身份允许时才显示“听话值”，否则显示“默契值”。底层始终只有一个 rapport；关掉任一许可会即时重绘属性、结算摘要、事件和历史手记，数值不重置。家长、宿管、楼管、辅导员等身份不能开启扮演，自定义身份使用这些管理称谓也会禁用。

## 互动、礼物与寝室小故事

在寝室页选择一位室友，下方“和 TA 的日常”即可操作。每名室友每游戏日最多 **3 次普通互动 + 1 次送礼**；扮演小游戏也占普通互动次数。对话消耗精力、整理消耗精力和体力；伸懒腰消耗 1 体力、恢复精力，精力不足时可提前伸展恢复；体力归零会进入请假休养，详见下方状态规则。正向属性收益经过专业倍率、共享进度额度与 0–100 边界，反馈显示实际增减。扮演需双层自愿许可且身份允许，可随时关闭。

如果当天没有给某位室友安排普通互动、送礼或身份行动，日结算时，TA 会从“聊聊今天、桌面整理接力、一起伸个懒腰”中随机选择一次负担得起的日常互动。每位室友独立判断，覆盖全部寝室；已经手动安排的室友沿用玩家选择。自动日常使用相同成本和成长规则，记录实际增减，卡片和日记显示“自动日常”。自然恢复后才选择；请假中的室友不安排自动日常，按休养规则恢复。旁观者视角也能观察室友的自主日常。

心意点为存档内资源，初始 20、每次日结算补给 8，上限 9999；礼物消耗 4/6/8 心意点及少量精力，事件也可能增减。资源不足会禁止操作并解释原因；刷新不能重置次数或重复领奖，下一天才恢复本日额度。

- **26 个故事、8 个分支**：零食分享、网络维修、粉色便签、阳台伸展、朗读、保温杯、小合唱、独卫镜边造型，以及洗漱篮、缎带舞台、周末提案、雨天窗边四个选择故事，以及大扫除、查寝、辅导员关心、家长电话/探望和室友穿搭交流六个身份故事。新增大扫除与家长电话有分支。本轮又加入集章小幸运、晴天散步、夸夸便签、作业截止、水杯打翻、找钥匙，以及停电/校园集市两个分支故事，既有正面也有负面效果。条件包含专业、设施、玩家身份、标签、好感、进度和游戏日；在结算第 2 天及之后才可能触发。
- **有条件、有随机性**：每寝室每天最多一个主要事件；有候选时基础触发率 78%，音乐专业在场提高为 93.6%。使用持久化种子，刷新与渲染不重抽。同一寝室的同一故事在当前周目只出现一次；条件不符、故事已用完或随机未命中时没有事件是正常情况。
- **分支留待你选**：“待选择的小故事”最多 3 个，满额后暂停新分支生成，无分支事件仍可发生。可点开、按 Escape 或“稍后再说”关闭，关闭不结算。所有分支至少有一个无需支付资源的选项。自动补天仅给出汇总，不弹出一串窗口或代替玩家选择。
- **奖励只结算一次**：选项、属性变化、资源、事件回执、服装解锁和日志统一提交；无效或资源不足时原状态不变。参与者的属性成本逐人支付，心意点只支付一次。延后处理使用选择当天的进度额度；关闭/刷新/重复提交不会重复获益。
- **事件解锁服装**：镜边造型可解锁云朵长卷发；缎带舞台选择新造型可解锁奶油花边衬衫；装饰雨天便签窗可解锁月光法师上衣。原有成长门槛仍可替代，服装不强制绑定专业、风格标签或扮演。
- **结算可解释**：摘要展示该日自然、互动、事件的实际增减及合计。日结算顺序为自然变化 → 未安排室友的自动日常 → 当日随机事件 → 每日补给 → 新一天；当天已做的互动与这些变化共享进度 +3 账本。自动日常始终使用普通校园表达，其余结构化历史随当前自愿设置重新显示，底层只有一份默契。

## 身份行动、面容与随机专业

在自定义工坊可选六种面容：温柔杏眼、元气圆脸、清冷细眼、乖巧垂眼、猫系雀斑、书卷眼镜。眼型、眉线、嘴角、雀斑或眼镜同步全身预览和地图头像。新建角色默认“随机分配专业（未指定）”，从计算机、艺术、体育、文科、医学、音乐中按存档种子抽取一次；明确选择日常或自定义则保留选择，编辑现有专业不会自动重抽。

寝室页的“身份专属行动”让所有身份都能参与：寝室长大扫除（宜居度 +12、每人消耗体力 6/精力 3、增加好感和默契）；宿管/楼管/辅导员预约查寝；家长打电话或预约探望；室友学习搭子；隔壁茶话会；旁观者分享观察；自定义身份安排小计划。每间寝室每天共用一次，改身份和刷新不重置，原有管理权限不改变；玩家身份不会自动占床。成本逐人支付，心意点全寝室只扣一次，任一参与者资源不足则整次取消。

宜居度在 0–100 之间，默认 60，达到 80 时日结算自然心情与体力各 +1，低于 30 时自然心情 -1，仍受自然变化 ±15 限制。身份行动不另刷进度额度，所有来源正向进度每日合计最多 +3；未使用起步加成时至少需要 34 次结算才能从 0 达到 100，体育自然成长通常更慢；选择男娘标签起步 50，阶段完成仍需进度 100 和至少 30 次日结算。

## 换装与搭配收藏

从导航的“换装衣柜”或寝室“给室友换装”进入 `#/wardrobe`；后者会选中当前室友。新玩家需要先完成入住。默认衣柜共用，角色造型独立；所有室友可自由选风格，不绑定专业或标签，管理权限沿用身份规则。

- **六槽 32 件**：开放发型、上衣、下装、裙装、配饰和妆容。新增樱花百褶裙、星月蓬蓬裙、蝴蝶结、腮红妆以及四件女仆妆造。全身预览分层展示，地图头像同步面容、发型、上衣、头饰与妆容。外套、独立鞋袜和高级配色仍置灰。
- **配色**：可调整发色、上衣色、下装色，先在试衣镜预览，点“应用配色”后才保存并同步地图。“还原预览”放弃本次颜色草稿；有未应用配色时暂停其他穿搭操作，避免保存与预览不一致。
- **主线与穿戴门槛**：男娘值与原养成进度共用一个 0–100 数值。每位室友达到 50 才能穿新增裙装/蝴蝶结/腮红，达到 100 才能穿女仆泡泡袖、黑白蕾丝围裙、头饰与人偶妆，并可一键成套穿戴。全局收藏不代替个人门槛，随机与收藏套装同样遵守；旧有衣物和已保存造型不追溯锁定。
- **成长解锁**：任一室友进度达到 15/45，或好感达到 50 时解锁对应衣物。解锁永久保留在当前周目，数值下降或室友离开不会收回。日结算与有效状态提交统一处理，并记录“衣柜上新”日志。
- **纪念事件**：保存第一套搭配触发一次“第一套造型”，解锁奶油双丸子与小鸭条纹裤。反复保存、删除、刷新不会重复发放。该事件为 M3 固定穿搭纪念，不代替 M4 的随机日常事件。
- **套装**：为当前造型命名并收藏，保存六槽衣物和三种配色；可给其他室友应用，最多 50 套。删除需确认，只删除收藏，不改变已穿造型。套装不会更改肤色、床位或成长。
- **随机搭配**：只在当前已解锁且该室友进度允许的对应槽位中抽取，使用存档随机种子；渲染和刷新不会重新抽取。换装、随机、配色和套装操作均不增加六维，不消耗体力，不受关系扮演开关影响。

## 后果预览与主动恢复

普通互动、主动恢复、礼物、身份行动和事件分支会在操作前显示**结算后的净变化**。预览复用实际专业倍率、取整、0–100 边界、当天进度额度和归零规则，包含精力归零引发心情归零、好感/进度减半及妆造收起的连锁后果；显示每位相关室友、实际心意点和宜居度变化。集体行动的逐人明细可展开查看，重要风险始终显示。不可执行的操作展示资源/权限/次数原因，不把它当作可执行的预告。

查看预览、展开明细和切换礼物不会消耗资源、推进随机种子、创建回执或修改存档。操作提交时仍按当前有效状态复验；预览只说明这次操作的确定效果，不预言之后的随机故事。

寝室“和 TA 的日常”下新增“主动恢复”。每次占用 **1 次普通互动**，与原有日常共享每人每天 3 次额度，可重复选择，送礼仍独立每天 1 次；刷新、切槽和 JSON 恢复均不重置当天次数。

| 恢复操作 | 额外资源成本         | 基础效果（专业与边界前）   |
| -------- | -------------------- | -------------------------- |
| 午睡片刻 | 无，消耗普通互动次数 | 精力 +12、体力 +4、心情 +2 |
| 食堂加餐 | 心意点 6             | 体力 +12、精力 +5、心情 +3 |
| 校园散步 | 体力 3               | 心情 +9、精力 +4           |
| 室友安慰 | 精力 2               | 心情 +8、好感 +1           |

卡片显示的是角色实际所得，例如计算机专业午睡的精力恢复经过现有 0.8 倍率取整为 +10。恢复操作不直接增加男娘进度；资源不足或请假时无法执行。请假仍按原来的七天日结算自动恢复，不因午睡提前返寝。午睡的无货币入口让心意点不足时也能安排恢复；四种主动恢复由玩家选择，自动日常继续只抽原有三个动作。

本次扩展沿用 schema 1.6 的既有互动计数、回执、日志与六维，旧档可直接继续。包含四种新动作的备份请使用本次或之后的构建恢复。

## 起步标签、归零后果与休养

- **男娘标签起步 50**：新建或首次选择“男娘”标签时，进度不足 50 补到 50，高于 50 不降低。每个角色只发放一次；编辑、删除/重加标签、刷新或当前档导入不能补领损失。初始配置加成独立于日常成长，后续所有正向进度仍共享每日 +3 额度，阶段完成仍要求至少 30 次日结算。
- **体力归零**：立即请假 7 个游戏日，界面显示剩余天数和返寝日；暂停普通互动、送礼、自动日常、集体行动、随机事件参与和男娘成长。可手动下一天或正常自动结算，不需要等待现实一周。休养每天恢复体力 12、精力 10、心情 6，数值上限 100；七次结算后返寝。其他室友仍可正常活动，集体行动不向休养者收取成本。原有待选故事保留，涉及休养者的选择暂缓至返寝。
- **心情归零**：好感与男娘进度各减半、向下取整，扣减不会返还当天已用的成长额度。低于 50/100 穿戴门槛时自动收起对应妆造，女仆上衣换回基础上衣；衣柜解锁与收藏套装保留，恢复进度后可重新穿戴。
- **精力归零**：心情 -5、默契 -2，可能进一步触发心情归零后果。每一段连续归零状态只触发一次；恢复为正数后再次归零会重新触发。标记和请假日期随存档保存，刷新、重复操作和打开弹窗不重复扣减。
- **结算与随机性**：归零后果是独立的状态事件，记录实际变化，并计入日结算的事件来源；自然变化本身继续限制 ±15。新增故事含好运、恢复、奖励与意外损失，分支显示成本和正负变化，仍由玩家选择，关闭不结算。

## 成就、图鉴与新周目

导航“星光纪念册”进入 `#/collection`，可搜索和浏览 8 项成就、室友造型、32 件服装及 26 个事件。达成入住、首套搭配、一周成长、多寝室、好感与默契、完成事件、阶段养成、新周目等目标后自动记录，并提示“成就解锁”。领取不依赖重复点击。

- 角色图鉴按稳定 ID 保存姓名、专业、配色与完整造型，编辑后更新最近的造型，离开寝室或开启新周目后仍可回看。最多 1000 张档案；满额会在图鉴提示，已有回忆保留，不自动删除腾位。
- 服装图鉴记录曾经获得的物品，事件图鉴记录已经完成的故事；尚未选择的分支继续等玩家决定。图鉴收录与当前衣柜解锁分开，跨周目回看不直接发放衣物或属性。
- 任一室友同时满足**男娘进度达到 100、已完成至少 30 次日结算**，寝室页会显示阶段完成入口。纪念册中可以继续当前故事，或二次确认“开启新周目”。取消确认不改变故事。
- 新周目只重置当前槽的室友、寝室、天数、互动账本、日志、资源、衣柜搭配和临时事件/解锁；保留槽名、玩家视角、音效偏好、累计周目数、成就和图鉴。关系许可恢复默认关闭，计时从现在重建。其他槽不受影响；存储失败时保留原故事。
- 每一周目都需重新达到阶段目标才可再开新周目。原有存档升级后，从当前仍存在的角色与回执收录可验证的回忆，不凭空补造已经丢失的历史人物或事件。

在“偏好设置”可以开启本地音效并试听，默认关闭、每槽独立。互动、换装与日结算后播放原创短提示音；关闭立即停止。浏览器未允许播放时会提示先试听，页面初始化不会凭空播放声音。

## 离线与应用更新

1. 首次联网打开**生产版本**，等待顶部“✓ 已准备好离线使用”。之后可以断网关闭/重开、直接打开 hash 页面、换装和继续日结算；此前未访问过的功能页也已缓存。第一次从未安装过此站点时仍需联网。
2. 浏览器支持时，可使用浏览器自己的“安装应用”或“添加到主屏幕”；PWA 图标、manifest、资源和音效均为本地文件。开发服务器 `npm run dev` 不启用 Service Worker，需 `npm run build` 后 `npm run preview` 验证离线。
3. 新资源完整缓存后，应用提示“保存并更新应用”；当前进度可靠保存后才切换版本并刷新。存档异常或尚有未保存进度会阻止更新，避免主动刷新丢失内存进度。其他标签页不会被强制刷新。
4. 缓存按真实站点子路径和构建内容散列隔离，只清理本应用同路径的旧版本，不清除存档或其他应用缓存。有其他旧标签页时暂留旧资源，使未加载过的旧页面分块也可继续读取，后续单页升级再清理。HashRouter 的根路径/项目子路径、快进参数均兼容。离线安装失败会如实提示，在线玩法仍可继续。

本地已用 Chrome 桌面、375px 触屏模拟和 Firefox 验证基础流程。Safari、手机真机、系统安装界面与实际 GitHub Pages 线上仍待验。
